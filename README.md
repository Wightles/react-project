# Чат Telegram

Тестовое задание на позицию frontend-разработчика: интерфейс отправки и получения текстовых сообщений Telegram через GREEN-API. Внешний вид сохранён по предоставленному макету чата MAX.

## Текущий этап

Готовы интерфейс, подключение к GREEN-API, поиск получателя в Telegram, отправка и получение текстовых сообщений. Уведомления обрабатываются через HTTP API, без отдельного сервера.

Реализованы поиск по номеру или имени в созданных чатах, отдельные черновики, многострочные сообщения, состояния загрузки и ошибки. На мобильном экране список чатов и переписка открываются по очереди.

Приложение начинает работу с пустым списком чатов. Сообщения, черновики и данные подключения хранятся только в памяти вкладки и сбрасываются при обновлении страницы или отключении. Токен не записывается в localStorage или sessionStorage.

## Стек

- React + TypeScript.
- Vite для разработки и сборки.
- CSS без UI-библиотеки.
- Fetch API для запросов к GREEN-API.
- Oxlint для проверки кода.
- Встроенный тестовый раннер Node.js для тестов API-клиента.

## Запуск

Используйте Node.js 24 и npm.

```bash
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале.

## Подключение и отправка

1. Создайте инстанс **Telegram** в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте его по [инструкции сервиса](https://green-api.com/telegram/docs/before-start/).
2. Скопируйте `apiUrl`, `idInstance`, `apiTokenInstance` из карточки этого инстанса в форму приложения. Значение `apiUrl` должно быть HTTPS-адресом сервера на поддомене `green-api.com`, без пути и параметров. Используйте параметры именно Telegram-инстанса. Токен BotFather для этого подключения не подходит.
3. Нажмите «Подключиться». Приложение вызовет `GetStateInstance` и продолжит работу только при состоянии `authorized`. Если требуется авторизация, запуск инстанса или снятие ограничений, в форме появится пояснение.
4. Введите международный номер получателя или `@username` и нажмите «Создать чат». Метод `CheckAccount` получает настоящий `chatId` Telegram. Международные номера вводятся с кодом страны; пробелы, скобки и дефисы удаляются. Российский префикс `8` преобразуется в `7`. Если номер скрыт настройками приватности, попробуйте `@username`. Поддерживаются личные чаты; группы и каналы не входят в задание.
5. Введите текст до 4096 символов и нажмите кнопку отправки или Enter. Shift + Enter добавляет новую строку.
6. После успешного `SendMessage` сообщение появится в переписке со статусом «В очереди». Это подтверждение приёма GREEN-API, а не доставки получателю. При включённых уведомлениях о статусах он обновляется на «Доставлено», «Прочитано» или «Не доставлено».

При ошибке отправки текст остаётся в поле ввода. Пока запрос выполняется, повторная отправка заблокирована. При потере ответа, таймауте или ошибке сервера результат может быть неопределённым: приложение предлагает проверить Telegram перед повтором и не повторяет запрос автоматически.

Кнопка «Отключиться» находится в настройках. Она очищает данные текущей вкладки, но не разлогинивает инстанс в GREEN-API. Во время отправки отключение недоступно до завершения запроса.

## Получение сообщений

В личном кабинете GREEN-API откройте настройки Telegram-инстанса:

- Оставьте `webhookUrl` пустым.
- Включите `incomingWebhook` – «Получать уведомления о входящих сообщениях и файлах».
- Для статусов включите `outgoingWebhook`, `outgoingAPIMessageWebhook` и `outgoingMessageWebhook`.
- Для отслеживания авторизации включите `stateWebhook`.

Сохраните изменения и подождите около минуты. Приложение проверяет настройки методом `GetSettings`, но не меняет их автоматически. Если проверка не пройдена, исправьте настройки и нажмите «Проверить снова» в верхней части интерфейса.

После подключения запускается последовательный цикл `ReceiveNotification` → обработка → `DeleteNotification`. Сервер ожидает событие до 5 секунд; клиентский таймаут – 20 секунд. Одновременно выполняется один запрос цикла, без `setInterval`. Отключение и размонтирование компонента отменяют запрос и ожидание повтора.

Обычный текст и текст с URL показываются в соответствующем чате. Для нового собеседника чат создаётся автоматически; при скрытом номере отображается имя или ID. Ответить можно по известному `chatId`. Сообщения, отправленные с телефона или другого клиента, также отображаются при включённых уведомлениях.

Повторы не добавляют сообщения заново: учитываются чат, ID сообщения и направление. Сбой `DeleteNotification` повторяет подтверждение уже обработанного уведомления. Сетевые ошибки повторяются с задержкой от 1 до 30 секунд; ошибки доступа или настроек приостанавливают опрос. Статусы, пришедшие раньше ответа `SendMessage`, сохраняются и применяются после появления сообщения.

Приложение предназначено для текста в личных чатах. Уведомления о медиа, группах и неизвестных типах подтверждаются, но не отображаются, чтобы очередь продолжала обрабатываться. Повреждённое текстовое уведомление не удаляется: получение останавливается с сообщением об ошибке.

Используйте один клиент очереди для этого инстанса: другой потребитель HTTP API может забрать уведомление первым. Подтверждённые уведомления удаляются из очереди GREEN-API; история чата с сервера не загружается и после обновления страницы не восстанавливается.

Для реальной проверки отправьте текст второму аккаунту Telegram и ответьте с него. Входящий ответ должен появиться без обновления страницы.

## Проверки

```bash
npm test
npm run lint
npm run build
```

Тесты API-клиента подставляют ответы `fetch` и не отправляют настоящие сообщения. Они проверяют адреса и тела запросов, авторизацию, проверку получателя по международному номеру и @username, лимит текста, HTTP-ошибки, таймаут, отмену и отсутствие автоматических повторов. Для запуска тестов используется поддержка TypeScript в Node.js 24, отдельный тестовый фреймворк не требуется.

Сборка проверяет типы TypeScript и создаёт приложение в `dist`. Для локального просмотра сборки: `npm run preview`.

Интерфейс проверен в Chrome с подставной очередью: входящий текст, ссылки, повтор события, сбой подтверждения, ранний статус доставки, новый собеседник, ответ без номера телефона, отключение во время опроса, повторное подключение и мобильная вёрстка. Обмен через реальный авторизованный инстанс пока не проверен.

## Структура исходников

- `src/App.tsx` – состояние подключения, чатов, черновиков и отправки.
- `src/api/greenApi.ts` – запросы, проверка ответов, таймаут и понятные ошибки.
- `src/api/notifications.ts` – преобразование уведомлений в события приложения.
- `src/api/notificationLoop.ts` – последовательный опрос, подтверждение и повтор при сбое.
- `src/hooks/useNotifications.ts` – жизненный цикл получения в React.
- `src/state/chats.ts` – объединение сообщений, защита от дубликатов и статусы доставки.
- `src/components/ChatList.tsx` – поиск и список чатов.
- `src/components/ChatWindow.tsx` – переписка, ошибки отправки и поле сообщения.
- `src/components/SidebarForm.tsx` – подключение и создание чата.
- `src/components/Icon.tsx` – иконки и аватар.
- `src/types.ts`, `src/utils/format.ts`, `src/constants.ts` – типы, форматирование и лимит сообщения.
- `tests/greenApi.test.mjs`, `tests/notifications.test.mjs` – проверки API-клиента, обработки событий и цикла получения.
